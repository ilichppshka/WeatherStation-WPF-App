# Архитектура WeatherStation

Решение состоит из [приложения WPF](../src/WeatherStation/WeatherStation.csproj) и [тестового проекта](../tests/WeatherStation.Tests/WeatherStation.Tests.csproj). В текущем каркасе [Program.cs](../src/WeatherStation/Program.cs) запускает WPF, управляет жизненным циклом .NET Host и регистрирует зависимости приложения. Пользовательские сценарии описаны в [спецификации](spec.md).

## Организация по функциям

Целевая структура строится по принципу feature-first. Код погоды, городов, журнала наблюдений, датчиков, предупреждений и настроек группируется по функции. Границы Clean Architecture применяются внутри каждой функции в одном WPF-проекте. Каталоги и контракты появляются по мере реализации сценариев.

| Слой | Ответственность |
| --- | --- |
| `Domain` | Сущности, значения и правила предметной области. |
| `Application` | Пользовательские сценарии и контракты для операций с хранилищем или внешними источниками. Зависит от `Domain`. |
| `Infrastructure` | Реализация контрактов `Application`, например клиент Open-Meteo и хранилище SQLite через EF Core. |
| `Presentation` | XAML, состояние экрана, ViewModel и команды `CommunityToolkit.Mvvm`. Вызывает сценарии `Application`. |

`Domain` и `Application` должны работать независимо от WPF, EF Core и конкретных HTTP-клиентов. Связи между функциями проходят через их публичные сценарии и контракты. Реализации для этих контрактов связываются при запуске через .NET Host.

Оболочка приложения отвечает за главное окно и навигацию. Общая техническая инфраструктура относится к `Core`, а элементы интерфейса, темы и конвертеры, которыми пользуются несколько функций, относятся к `Shared`.

## Пример сценария

При сохранении текущей погоды в журнал ViewModel вызывает сценарий записи наблюдения. Сценарий применяет правила предметной области и сохраняет запись через контракт хранилища. Реализация хранилища работает с SQLite, а ViewModel показывает результат пользователю.
